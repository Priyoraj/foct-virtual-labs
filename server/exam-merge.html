3. Merge and check

Leave out code that more than % of the students have (standard solutions and the lines everyone writes)

How the check works

  • Each program is compared with every other program of the same lab, as MOSS and JPlag do: names, numbers, texts, comments and spacing are set aside, so renaming variables or changing messages does not hide copying, and the longest shared stretches are found in any order, so moving functions around does not either.
  • Code you gave the students and code most of the class has does not count. The report shows what was left out.
  • For each pair the report says how much of each student's own code is in the other's work, shows the matching parts side by side in colour, and says how it matches: copied as it is, names changed, parts moved, identical comments, identical files. Each student's exam alerts are next to it.
  • Similarity is evidence, not proof: look at the matching parts and ask the students to explain. Record a decision on each pair; the CSV goes into your marks sheet.
  • Everything stays on this PC. Nothing is sent anywhere (MOSS, by contrast, needs the students' code sent to its server in the USA).

With several lab servers

  • Start the exam on every server with the same title, options and exam code.
  • If a server stops, its students open another server's address and sign in again. What they had sent stays on the first server; once it is back, download its zip too. Their newest copy of each file ends up in their folder, older copies in Other copies.
  • Work a student had not sent yet stays in that browser for the first server's address: a new address is a new start.
  • Keep the servers' clocks right: "newest" means newest by each server's clock.
