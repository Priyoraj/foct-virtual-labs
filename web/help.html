FoCT Virtual Labs — Help

Every lab runs inside your web browser. The lab server only sends the programs to your browser; it never runs, receives or stores your work.

Getting started

  1. Open the lab address your teacher gave you (for example http://labserver:8080) in Google Chrome or Microsoft Edge (Firefox also works).
  2. Pick a lab on the home page. The first time, a lab may take 10–30 seconds to load; after that it is cached by the browser and opens quickly.
  3. In the code labs press Run (Ctrl+Enter). When your program asks for input, type in the Output panel and press Enter.

Saving your work

Nothing is saved on the lab server. Keep your files on your own computer, pen drive or cloud drive.
  • Code labs: Save (Ctrl+S) downloads the file (or, in secure mode, lets you choose where to save it and later saves straight back to it). Open (Ctrl+O) loads a file. The menu has Download all files (.zip).
  • Jupyter notebooks: notebooks live in this browser only. Use File → Download to keep the .ipynb. Use the upload button (↑) to bring a notebook or a data file back.
  • Diagrams: File → Save as / Export as (PNG, SVG, PDF) saves to your computer.
  • MongoDB Lab: your databases stay in this browser between visits. Save databases writes them all to one .json file (open it again with Open databases); Export saves one collection as JSON or CSV, as mongoexport does; Save keeps your script as a .js file.
  • Compiler design tools: your last grammar, expression and statements are remembered in this browser; print the page (Ctrl+P) to keep the tables as a PDF.
  • SQL Lab: Save keeps your script as a .sql file; Save database keeps the whole database (.sqlite for SQLite, .pgdata.tar.gz for PostgreSQL) so you can open it again later.
  • SPICE simulator: Save keeps the netlist as a .cir file; CSV and PNG save the results and the plot.
  • Circuit simulator: File → Save As downloads a .txt circuit file; File → Open File loads it.
  • Network simulator: Save keeps a .foctnet file; Open loads it.
  • Office: Ctrl+S or File → Download as saves .docx, .xlsx, .pptx or PDF.
  • Unsaved code is kept as a draft in this browser so a refresh does not lose it. On a shared PC, press Clear my lab data on the home page before you leave.

Secure mode (HTTPS)

The labs work over plain http://. Opening them over https:// with the lab certificate (secure mode) adds:

  • the full Java 21 runtime (instead of basic mode),
  • Jupyter notebooks that can read uploaded files and use input(),
  • saving straight back to the same file on your computer,
  • offline caching for faster start-up.

Install the lab certificate on a PC (once per PC)

Windows (Chrome / Edge):

  1. Download foct-lab-ca.crt and open it.
  2. Click Install Certificate… → Current User → Place all certificates in the following store → Browse → Trusted Root Certification Authorities → Finish, then Yes on the security warning.
  3. Restart the browser and open the https:// address shown on the server window (port 8443).

Administrators can install it for all users from an elevated command prompt:

certutil -addstore -f Root foct-lab-ca.crt

or push it with Group Policy (Computer Configuration → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities). If the labs are re-imaged for exams, include the certificate in the lab image.

Firefox: Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import, tick “Trust this CA to identify websites”.

Linux (Ubuntu):

sudo cp foct-lab-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates

The certificate can only vouch for addresses inside the lab network (private IP ranges and local names), so it cannot be misused to impersonate real websites.

Troubleshooting

  • A lab is slow the first time: the browser downloads the compiler or Python once (C about 30 MB, C++ 40 MB, Python 20 MB with NumPy and Matplotlib, Jupyter 50 MB, Java 6 MB or 54 MB for full Java, Office 19 MB, SPICE and diagrams 7 MB each, SQL and MongoDB 2 MB, PostgreSQL 5 MB more). The first Lex & Yacc run on a PC builds lex and yacc (about 20 seconds). Later visits use the browser cache.
  • “Update browser” on the home page: use a current Chrome, Edge or Firefox (2024 or newer).
  • The program waits forever: it is probably waiting for input — type in the Output panel. Use Stop to end a program that loops forever.
  • Out of memory / blank page: close other tabs; the Office and Java labs need a PC with at least 4 GB of RAM.
  • Lost work: open the same lab on the same PC and browser: the last draft is restored automatically.

For lab administrators

Start the server on any PC of the lab network (Windows, Linux or macOS with Python 3.8+):

start-server.bat            (Windows: double-click)
./start-server.sh           (Linux / macOS)
python server/serve.py --https    (also serve secure mode on port 8443)

The window shows the addresses to give to students. Allow the program through the firewall when Windows asks (or run server\allow-firewall.bat as administrator). The server needs very little CPU: all compiling and running happens on the students’ PCs. Live statistics: /__status.

Large labs (for example 90 PCs): one ordinary PC is enough as the server. In a test it sent the C compiler to 90 clients at once at about 885 MB/s, far more than a gigabit network can carry, so the network is what matters.

  • Connect the server to the lab’s main switch with a cable at 1 Gbps. Do not use Wi-Fi.
  • On a PC’s first visit a lab downloads up to 50 MB. If 90 PCs open Jupyter for the first time together, this takes about 40 seconds on gigabit, or several minutes at 100 Mbit/s.
  • After that, browsers keep the runtimes for 30 days. Opening a lab again needs only a few small requests.
  • Runtimes are downloaded again only after tools/setup.py installs a new version.
  • After the PCs are re-imaged, open each lab once on every PC before class.
